=== v2.5.2 真机验证：歌词「整条居中」几何 A/B ===
设备：S6 / SM-G9209 / Android 7.0 (API 24) —— 目标下限设备
形态：**大屏模式**（2560×1440 横屏，歌词面板 = 右栏）
测量：`uiautomator dump` 取节点 bounds（面板视口 + 当前条目的原句行与译文行）
协议：进入大屏模式 → 在面板上手势把歌词推走 → 等 9s（5s 无触碰自动居中落地）→ dump

############ 修复前（debug 42 / v2.5.1 代码）############
面板     : y 96..1024  h=928  中心=560
当前条目 : y 600..847  h=247  中心=724   行数=2
   y   600..  747  'I cannot cry'
   y   755..  847  '我不能哭'
条目中心占面板比例 = 67.6%   （理想 = 50.0%）

偏离面板中心 = +164px        ← 整块的视觉中心掉在下面，这就是用户报的"痛苦"

############ 修复后（43 / v2.5.2 代码）· 同一台设备同一协议 ############
面板     : y 96..1024  h=928  中心=560
当前条目 : y 414..773  h=359  中心=594   行数=2

   y   693..  773  '人生的轨道我从不敢偏移半分'
条目中心占面板比例 = 53.6%   （理想 = 50.0%）
偏离面板中心 = +34px

############ 结论 ############
条目中心 67.6% → 53.6%，向上修正 130px（≈37dp）。
残余 +34px 是**字体 leading 的几何差**（条目盒已严格居中；uiautomator 量的是字形框，
比行盒小，上下留白不对称），不是定位错误 —— 修法居中对象是「条目盒」，
因为那是布局层唯一可测量的东西。

公式复核（修复后这一条）：
  条目高 = 文字 359px + 上下 padding 2×10dp(=70px) = 429px
  期望顶边 = 96 + 928×0.5 − 429/2 = 345.5px  ＞ 顶部渐隐下限 min(100dp=350, 928×0.3=278)=278
  ⇒ 文字顶边期望 ≈ 345.5 + 35 = 380.5px，实测 414px（差 33.5px = 上述 leading 差）
