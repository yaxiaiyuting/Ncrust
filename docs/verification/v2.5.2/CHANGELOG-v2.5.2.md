# Ncrust v2.5.2-gpl 更新说明（用户可读）

> 这是一版**紧急修复**：歌词自动居中。

## 修了什么

**歌词自动居中以前只把「第一行」居中**，整条歌词（原句 + 译文 + 音译）会往下坠 ——
**行数越多偏得越狠**，所以带翻译的歌最明显，大屏模式（横屏 / 平板右栏）里尤其难受。

现在改成：**把这一整条（原句 + 它的译文 + 音译）的中点放到目标位置上。**

### 大屏模式下的实测（S6 / Android 7.0 / 带翻译的歌）

| | 整条歌词的视觉中心落在面板的 |
|---|---|
| 修复前 | **67.6%**（明显偏下，顶边看着像"居中了"，其余行全掉在下面） |
| 修复后 | **53.6%**（≈ 正中；剩下的 3.6% 是字体行高与字形框的固有差别） |

也就是整条**往上提了约 37dp**，上一句与下一句重新分列它的上下。

### 具体做了什么

1. 定位目标从「**这一条的顶边**」改成「**这一条的中点**」；
2. 一条歌词的高度**按实际排版量出来**（折行、译文、音译都算进去），
   量不到时先按旧行为摆一次、紧接着用实测高度纠正 —— **不会比以前更差**；
3. 增加一条保护：整条**永远不会顶进上方的渐隐带**（否则当前行会发灰看不清）；
   条目比面板还高时退化成"顶对齐"（滚动容器的通用行为）；
4. 渐隐带高度从此只有一处定义（面板要用它算"最高能摆到哪"）——
   以后调渐隐不会出现"渐隐变了、定位没跟上"。

### 顺带修的隐患

- 高度缓存刻意**不参与 Compose 重组**（用普通 Map 而不是 state map），
  避免"每次布局都重组一次歌词面板"这种典型的动画期掉帧来源。

## 没做什么

- **没有改任何动效参数**（时长 / 曲线 / 位移一律未动）；
- **没有改竖屏的目标比例**（仍是 36% 高处，只是从"顶边"改成"整条中点"）；
- **没有引入新的设置项**。

## 这一版没验证到的（如实）

- 竖屏下的同协议 A/B 这次没取到（退出大屏后歌词面板未挂载）；
- 平板的 A/B 没做（该机型的 UI 自动化工具被系统杀掉）；
- 「顶边不得进渐隐带」这条夹取在真机上没有被触发过（只有单测覆盖）。

详见 `EVIDENCE.md` §6。
