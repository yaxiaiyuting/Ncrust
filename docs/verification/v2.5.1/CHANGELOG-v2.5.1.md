# Ncrust v2.5.1-gpl 更新说明（用户可读）

> 这一版在 v2.5.0 的基础上补了一件事、关了几个遗留验证缺口。
> 完整证据索引见 [`EVIDENCE.md`](EVIDENCE.md)。

## 一、新增：页面切换动效**可以自己关了**

从这一版起，**页面之间的切换有了过渡动效**（新页面从右侧滑入 + 淡入，260ms）。
这是 v2.5.0 里**故意没做**的那一项 —— 当时的理由是「低端机上转场是掉帧的主要来源」。
理由本身没错，所以这一版没有把它变成硬开关，而是**交给你**：

**设置 → 用户 → 播放 → 「页面切换动效」**

| | |
|---|---|
| 默认 | **开**（有过渡动效） |
| 关掉之后 | 页面**直接跳变**，行为与 v2.5.0 **逐字节相同**（零中间帧、零动画计算） |
| 说明文字 | 「关闭可提升低端机流畅度」 |

**改完立即生效，不需要重启**：关掉之后，下一次点进详情页就已经没有动画了。

### 为什么默认是「开」，而不是默认关

因为你装了 v2.5.0 之后**没有做过这个选择** —— 「没有转场」是当时的产品决定，不是你的决定。
所以升级后默认给你动效；不想要，关一次就永久记住（重启后仍然是关）。

## 二、这一版的动效到底有多耗性能（**在真机上量过了**）

在 S6（Android 7.0，本应用支持的最低档设备）上用 **release 包**实测 90 分位帧时间：

| 场景 | 90 分位帧时间 |
|---|---|
| 列表滚动 | 19 ms |
| 播放页展开/收起 | 27 ms |
| 页面切换（**动效开**） | 36 ms |
| 页面切换（**动效关**） | 32 ms |
| 只测「返回」这一步（动效开） | 34 ms |
| 只测「返回」这一步（动效关） | 19 ms |

**怎么看这组数（不美化）**：

- 这台 2015 年的机器**在任何场景下都跑不到 60fps**，包括**动效全关**的那一列 ——
  这是既有事实，不是这一版造成的。
- 转场本身**确实有成本**：只测「返回」这一步时，开会比关多画约 15 帧/次，且那几帧更重。
  这正是 v2.5.0 当初那条理由的真实分量。
- 所以**「关掉它」是这台机器上真实有效的选项** —— 这也是把开关交给你的原因。
- 我们**试过**调参：把转场改成「不透明的整页位移」（去掉淡入淡出的混合）后重测，
  90 分位中位反而从 34ms 变成 **40ms**，于是回退了。**动效参数这一版没有动**。

> ⚠️ 上面每一个数字都来自 **release 包**。用 debug 包的耗时讨论性能是错的
> （debug 不经过 R8、代码更大更慢），这一版起这条写进了仓库的开发规则。

## 三、修好的 / 补上的遗留问题

1. **歌曲菜单第 10 条点不到**（v2.5.0 在 S6 上抓到的回归）
   —— 这一版在 **release 包**上复核：菜单滚动一次后，
   「单曲信息」落在 `[224,2411][468,2486]`，**10 条全部可达**。
   同时补了回归单测（菜单高度上限的纯逻辑），并确认这条**不是**只在 release 包出现的问题。
2. **页面转场的设置项持久化**：新增了 `page_transition_enabled` 字段，
   配套的迁移逻辑（老用户没有这个键 → 按默认「开」）与 10 条单测一起进仓库。
3. **文案预算**：新文案进了新的嵌套组，同时把「`Strings` 主构造器余量」这件事写进测试 ——
   现在余量是 **0**，下一个加文案的人必须先腾位置（否则真机启动即崩）。

## 四、Kanesumi 库的圆角：**上游限制，本版不改**

v2.5.0 给封面、卡片、列表项、按钮加了统一的圆角，但**库内部**的组件
（弹窗背板、部分按钮）**仍然是直角**。原因不是漏了，而是：

- Kanesumi 是本项目依赖的**外部库**（组合构建，不在本仓库的版本控制里）。
  改它会让发布产物依赖另一个仓库的**未发布提交**，`git clone` 之后**构建不出来**；
- 把库里的组件逐个复制进本仓库也会同样破坏「可复现」（v1.5.0 复制歌词面板时就是这条理由）。

所以本版如实记录这条边界：**圆角在 app 侧统一，库内部保持直角**。
「fork Kanesumi 并把圆角规范下沉进库」的成本评估**留到 v2.5.1 之后**，本版不做。

## 五、这一版**没有**验证到的（如实列出）

- **灰度封面回退默认主题**：只有单测证据，**没有**在真机上找一张灰色封面走一遍
  （已把主题色来源切到「跟随封面」并选好候选曲目，但设备验证被中止）。
- **单曲循环 / 顺序线性 / 无限三种模式**下「添加到下一首播放」的真机行为：
  仍只有单测证据（v2.5.0 那一轮跑的是随机模式）。
- **第二台设备（PLC110 / Android 16）的帧数据**：只完成了 release 包安装与数据保留，
  没有跑 `gfxinfo`。所以第二节的量化结论**只对 S6 成立**。

这三项都写在 `EVIDENCE.md` §6.2，下一轮优先补。

## 六、升级注意

- **versionCode 42 > 41**，可以直接覆盖安装 v2.5.0 及更早的 fork 版本。
- 与上游官方版（`com.takahashirinta.ncrust` 官方签名）**签名不同，不能互相覆盖**，
  切换需要先卸载（会丢失本地登录态与离线缓存）。
- **本版新增一个落盘字段** `page_transition_enabled`（`ncrust_settings`），
  老用户升级后按默认「开」处理，**不需要你做任何事**。
- **v2.5.0 的 draft release 已一并转正**（内容包含在本版里）。两个版本都可用；
  新装机建议直接用 **v2.5.1**。
