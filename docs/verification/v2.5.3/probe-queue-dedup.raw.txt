3) id 空间隔离的算术证明（结构事实，不是启发式）
==============================================================================
  QQ_ID_FLAG = 1L shl 62 = 4611686018427387904  (0x4000000000000000)
  网易云 songId 实测量级   : 1e6 ~ 3e9   （远小于 2^40 = 1099511627776）
  QQ 合成 id 的最小值      : 4611686018427387905  (bit62 恒置位)
  两个区间是否相交          : 否
  ⇒ 只要 QQ 曲目的 id 都经 `SourceIds.qqId()` 产出，
    「网易云 id == QQ id」在 64 位整数上**不可能**成立 —— 与抽样无关。

4) 抽样 1000 首双源配对：裸 id vs TrackKey 的冲突计数
==============================================================================
  样本数                        : 1000（网易云 × QQ 各 1 首配对）
  裸 song.id 上的**跨源**数值冲突: 0 次
  裸 song.id 上的同源重复        : 0（每首 id 唯一）
  TrackKey 上的冲突              : 0 次

  ── 关键限定（不许把结论说过头）──
  这个 0 **不是因为抽样运气好**，而是因为第 3 节的算术：
  样本里 QQ 的 id 由 `qq_id()` 产出（bit62 置位），网易云的没有。
  换句话说：**冲突发生率 = 0 是当前实现的结构性结果**；
  它成立的前提是「所有 QQ 生产者都走 qqId」—— 这正是第 2 节要逐点核对的事。

5) 同源内唯一性 + 兜底散列的碰撞
==============================================================================
  网易云同源      : id 就是平台 songId，平台内唯一 —— 无重复可能
  QQ 同源（有 songid）: 合成 id = bit62 | songid，songid 平台内唯一 ⇒ 唯一
  QQ 同源（无 songid，FNV-1a 散列 songmid 兜底）:
      抽样 20000 个 songmid → 0 个散列碰撞
      理论碰撞概率 ≈ n²/2^63 = 4.337e-11（62 位空间）
