## 打 tag 后的自证（tag 侧的第三源）

tag 必须打在「产出这批 APK 的那个提交」上。打 tag 前先自证一次：

```
$ git log --oneline -1
7905a59 fix(player): 乱序模式轮首的「上一首」静默无效 —— 回绕到轮末（真机受控复测 1/5 → 5/5）

$ git status --short
（空）

$ grep -n "versionCode\|versionName" app/build.gradle.kts | head -2
233:        versionCode = 46
234:        versionName = "2.5.5-gpl"
```

产物自证（**HEAD 就在 APK 里**）：

```
$ unzip -p app/build/outputs/apk/release/app-release.apk \
      META-INF/version-control-info.textproto
repositories {
  system: GIT
  local_root_path: "$PROJECT_DIR"
  revision: "7905a5958606e116a8aebf922bab42cb6d9dc71a"
}

$ git rev-parse HEAD
7905a5958606e116a8aebf922bab42cb6d9dc71a        ← 逐字相同
```

```
$ aapt2 dump badging dist/Ncrust-v2.5.5-gpl-release.apk | head -1
```

> ⚠️ 与 v2.5.3 记录过的同一条事实：**APK 不可逐字节复现**。
> 本版实测过一次（同一个 HEAD 两次构建之间只差一次提交 ⇒ sha 不同），
> 差异来自 `META-INF/version-control-info.textproto` 里的 git revision ——
> 那正是上面用来做「HEAD == 产物源码」自证的那一项。
> 因此**产物自证靠 VCS 戳，不靠 sha 相等**。
