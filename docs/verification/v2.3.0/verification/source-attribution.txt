## 3. QQ 歌单**一步可达**（任务书 3.1）

v2.2.0 的库页里 QQ 歌单是一个**入口行**（`QqPlaylistEntryRow`），点进去才是列表。
本版把**列表本身**放进这一页 —— `v230-03-playlists-scrolled.xml` 里 QQ 区的歌单
**直接平铺**在同一屏：

```
QQ 音乐                                   [64,1342][247,1403]
  我喜欢                                   [304,1526][487,1601]
  2 首 · 我喜欢                            [304,1601][564,1658]
  新建歌单1                                [304,1790][584,1865]
  22 首                                   [304,1865][416,1922]
```

⇒ 从库页到「看到 QQ 歌单内容」**不需要任何中间页面**。
`QqPlaylistScreen`（二级列表页）与其路由已随之删除（留一条没有入口的死路由没有意义）。

## 4. 空状态分两种（任务书 3.1）

| 状态 | 文案 | 判据 |
|---|---|---|
| QQ 未登录 | 「登录 QQ 音乐后可查看歌单」 | `PlaylistHardFailure.NeedLogin` |
| 已登录但确实没有歌单 | 「暂无歌单」 | 其它空结果 |

本机 QQ 已登录，所以实测看到的是有歌单的那一支；
两种空状态的判定在 `LibraryPlaylistsTab` 里是分开的两个分支
（`qqNeedLogin` 与 `qqOrdered.isEmpty()`），不是靠文案猜。

## 5. 双音源切换与登录态

- 网易云登录态：`ncrust_prefs.xml` 里 `MUSIC_U` 仍在（升级后未掉）；
- QQ 登录态：`ncrust_qq_prefs.xml` 里 `qq_cookie` 仍在；
- 库页「歌单」tab 的网易云区在冷启动后短暂显示加载指示器
  （`screenshots/v230-03-playlists-scrolled.png` 里的转圈），
  而 QQ 区**不受它影响**（两个区块各自加载）—— 这正是 v2.2.0 修过的
  「一个音源的加载状态绑架另一个音源的入口」在本版的延续。
